# Инвентарь

## Управление
- Tab — открыть/закрыть рюкзак; Esc — закрыть открытый инвентарь.
- E рядом с предметом/сундуком — подобрать/открыть.
- ЛКМ: перетащить весь стак между ячейками, в том числе между сундуком и рюкзаком.
- Одинаковые предметы объединяются до MaxStackSize; разные меняются местами.
- ПКМ в рюкзаке — использовать UsableItem. Зелье восстанавливает 25 HP и расходуется только при нехватке здоровья.
- Для выброса перетащить стак из рюкзака в нижнюю область.

В базовой сцене сундук рядом с точкой появления хоста (5.5, 0.4, -6.2), кристалл — около центра. В рюкзаке изначально три зелья. Тестовый слот экипировки не принимает предметы и не имеет механик.

## Ресурсы и компоненты
- Item: DisplayName, Model (PackedScene с корнем Node3D), MaxStackSize, Rarity.
- Редкости: Common/обычный, Rare/редкий, Epic/эпический, Mythic/мифический, Legendary/легендарный. Цвет и энергия света определены в Item.
- Stack: Item, ItemCount. Ресурсы Item общие, стаки копируются для каждого экземпляра инвентаря/подбираемого объекта.
- UsableItem: переопределить Use(Player), вернуть true только при успешном применении. Эффект выполняется сервером.
- InventoryComponent можно добавить дочерним узлом любого объекта. MaxSlots и начальный массив Slots настраиваются до входа в дерево (инспектор). Не занятые ячейки — null.
- В сетевой игре изменять инвентарь через InventoryService; Add/Transfer — серверные примитивы, сами RPC не отправляют. После серверных изменений вне сервиса вызвать Publish().
- Новые типы сетевых контейнеров подключаются через проверку доступа InventoryService.Resolve; Chest уже подключён.
- Для новых предметов сохранять Item отдельным .tres: по сети передаётся ResourcePath, одинаковый на всех клиентах. Модели демонстрационных предметов центрированы около нуля, размер около 0.7 единицы; так же готовить другие UI-модели.
- PickUpObj.Slot назначается до AddChild: при _Ready создаются модель и свет из Item. Выброс делает это автоматически.

## Состояния и сеть
PlayerStateMachine имеет состояния Locomotion, Inventory, Chest, Disabled и вложенные состояния движения Idle/Walking/Crouching/CrouchWalking/Airborne, события переходов, вход/выход и блокировку камеры/атак/движения. Во время инвентаря гравитация продолжает работать. Сундук закрывается сервером при удалении/выходе из допустимой дистанции.

InventoryService создаётся NetworkManager по одинаковому пути. Сервер проверяет отправителя RPC, дистанцию, доступ к контейнеру, индексы и ревизию. Устаревший перенос отклоняется: повторить drag после обновления. Все операции передают полные снимки инвентарей, pickup-объектов и открытых сундуков; это простой вариант для небольших сессий. Позднее подключение запрашивает актуальный снимок. Движение остаётся с существующей клиентской authority, как в исходной архитектуре.

MultiplayerSpawner единолично создаёт игроков на клиентах; authority назначается по имени узла до входа дочерних узлов в дерево.

## Проверки
```powershell
dotnet build --no-restore
& $godot --headless --path E:\YandexGame res://tests/inventory_tests.tscn
```
Для сетевого теста запустить два процесса (хост первым, клиент через 2 секунды):
```powershell
& $godot --headless --path E:\YandexGame res://tests/inventory_tests.tscn -- --network-host
& $godot --headless --path E:\YandexGame res://tests/inventory_tests.tscn -- --network-client
```
Тесты проверяют вместимость, overflow, перенос, закрытый сундук, устаревшие команды, лечение, выброс/подбор, состояния, реальную клиент-серверную репликацию и снимок при позднем подключении. Флаг --preview без --headless сохраняет изображение UI в %TEMP%/inventory-preview.png. Автоматические тесты вызывают те же серверные команды, что UI; ручные жесты мышью отдельно не автоматизированы.
